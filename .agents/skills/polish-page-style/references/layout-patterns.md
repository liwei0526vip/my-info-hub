# 内容与布局模式

选型先看读者任务，再看数据形态。先完成整页内容映射，再逐块实现；下列模式可组合，无需固定模板或区块数量。

## 表格与数据图如何取舍

- **查值和字段对齐：** 用表格。每个字段作为独立列；单位放表头，参数、状态、日期性质分别表达。保留排序、筛选等已有功能。
- **比较数值大小：** 用条形图；类别名称长时横向排列。保留零基线；需要细查时附表，而非在图上堆满标签。
- **看时间变化：** 用折线图，时间间隔按真实日期处理；有缺失值就断开或明确标注，不能补成零或自动插值。
- **看同一个整体的构成：** 用堆叠条或少量分类的构成图。不同口径或不同分母拆开呈现；不要把任意一组百分比拼成饼图。
- **看容量与上限：** 用进度 / 限额图，写清当前值、上限、单位及口径。单一数值通常用主值或键值块就够。
- 不同单位、安全等级、测量环境或样本范围可以并列展示，但不能在图上暗示直接可比。保留必要限定，不让“简洁”改变结论。

## 流程、时序、时间轴如何取舍

- **流程图：** 看怎么走、在哪里分支、依赖谁。节点表达动作或状态，箭头标注条件或传递内容。有独立泳道需求时先按参与方分组。
- **时序图：** 看多个参与方之间谁先发什么、谁回应什么。保留消息方向、交互顺序、阶段边界。只有日期的事件列表用时间轴。
- **时间轴：** 看发生时间、版本或历史顺序。日期只有年份就保留年份；预计节点与已发生节点有文字或图形区别。
- **步骤列表：** 短的线性操作不必制成复杂图。编号用于真实顺序，不能给平行分类制造先后关系。
- **树状 / ER 图：** 前者表达层级和归属；后者表达实体、字段、基数。横向比较字段仍用表格，避免把所有对象连成难读的网络图。

## 单块之外的整页组织

### 资料速查

核心对象或对照表靠前，常用字段直接可见；解释、少见参数和来源细节邻接或折叠。地址、产品资料等独立档案可用键值块，按主题分组。内容适合查阅时，不强制加入“大结论”或巨大首屏。

### 并列对照

同维度内容使用一致的列顺序、度量单位、状态词和视觉尺度。需要逐行对照的对象优先共享表格；各自具有较多独立结构的对象才用并排面板。保留能改变判断的例外条件。

### 机制解释

先呈现核心关系图，再把边界、状态与说明放在图旁或紧接其后。参与方的交互可用时序图，系统结构可用树或流程图；不要把同一关系在多张图与正文中重复解释。

### 历程与演进

以时间轴承载事件，把每个事件的名称、日期、状态和来源合在一个落点。仅对重要里程碑加强强调；多条相关轨道可并列，手机上按轨道依次阅读，不能破坏各自时间顺序。

### 多主题混合页面

围绕一个主任务安排骨架，例如“对象对照 → 所处阶段 → 工程影响 → 实现与迁移”。宽表、主图通栏；相互补充且内容量接近的区块并排；详情放在所属主题附近。

只有独立语义和边界的内容才需要面板。留白用于分组，分隔线用于划分信息层级，不给每个句子都加边框。并排高度差很大时调整配对或改顺序布局，不塞入重复文字补齐空白。

## 视觉拼装与响应式

- 先确定主信息、次级说明与参考细节的层级，再分配宽度与强调色。整页保留稳定的标题、图注、表头、来源样式。
- 新组件首先服从信息功能；站点设计令牌是视觉基础，不能代替组件选型。分类色保留清楚图例，语义色表达判断。
- 手机上的并排内容按阅读顺序堆叠。比较表保留表格关系，可展示核心列并提供其余字段的详情入口，或采用局部滚动、经过核对的卡片形式；不能直接丢掉字段。
- 图形太宽时优先改布局方向、分成真实阶段或局部滚动。维持可读文字和清楚的箭头，避免整图压缩到不可读。
- 折叠适用于低优先级详情；核心事实、会改变判断的限制和主要结论不藏在折叠里。

## 现有页面的迁移记录

复杂页面可在工作记录中用下表追踪，不要求在产品页面展示它：

| 原信息块 | 关系与阅读任务 | 新组件 / 区域 | 事实与功能的保留点 |
|---|---|---|---|
| 多个算法及参数 | 逐项查值与比较 | 通栏表格 | 参数、等级、日期性质、来源链接 |
| 多方握手过程 | 消息方向与顺序 | 时序图 | 参与方、消息、先后、阶段 |
| 标准发布时间 | 演进顺序 | 时间轴 | 日期精度、已发布 / 计划、官方链接 |
| 大小测量值 | 比较体积 | 条形图与明细表 | 字节单位、实例、测试条件 |
| 日历节日清单 | 按日期与分类查阅 | 紧凑表格或日期卡片 | 历法、日期、类型、习俗 |

这些是选型示例，不是要求把上述组件加进每个页面。已适合阅读的原表达可以继续使用。
