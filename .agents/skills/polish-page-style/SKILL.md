# 内容可视化与页面编排

把已有 HTML 中的信息转换为合适的表达，再组织成清晰、美观、便于查阅的完整页面。组件选型、阅读顺序、主次布局是核心；颜色和字号规范用于支撑整页设计。

用户本次明确要求优先；以下边界用于未额外授权内容更新或功能变更的页面编排任务。

可以重组 HTML、调整目标页 CSS、生成图表，并为展示增加必要的局部代码。简单内容保留简短文字；有明确关系或比较需求时，主动选用合适的组件，无须为任务范围内的每张图单独请求确认。

## 内容与功能保真

- 保留事实、数值、单位、日期、适用范围、状态、限定条件、不确定性与来源链接。先读完折叠区、标签页、嵌入数据和图注，再判断哪些内容可以归并。
- 允许调整段落顺序、按问题重新分组、合并重复内容和等义精简。合并后，每项独有事实仍有明确落点；限定语不能因去重而丢失。纯美化不自行更新数值、补充事实或删除独有信息；若用户同时授权内容更新，按该范围核验和处理。
- 保留现有导航、复制、筛选、排序、展开、跳转等功能与键盘可用性。改结构时核对原 JS 依赖的 ID、选择器和 data 属性；旧锚点保留或提供兼容落点，不删除仍被引用的钩子。
- 只处理用户指定页面及其必要资源。默认保留站点导航与基础设施，不改共享的 site-nav 文件；页面主题、布局和组件可以重做。共享样式改动须检查其他引用页，通常优先使用页面前缀隔离。
- 缺少图表数据、时间点或关系时，选择现有信息能够支持的表达。不要补造数值、把阶段当日期、把相关关系画成因果关系。

## 从内容决定组件

先判断读者在这一块需要完成什么：精确查值、比较差异、理解交互、追踪演进、查找归属，还是了解结论。按任务选型，不按原 HTML 标签或段落数量选型。

| 信息关系 / 阅读任务 | 优先表达 | 关键判断 |
|---|---|---|
| 多个对象共享字段，查值或逐项比较 | 表格 | 字段独立成列，单位、状态与来源不混写；过宽时缩短表头、分组字段或局部滚动 |
| 数量差异、随时间变化、整体构成 | 条形图、折线图、构成图 | 必须有真实、可比的数据；需要精确查值时保留明细表 |
| 多方按顺序收发消息 | 时序图 | 有参与方与消息顺序；日期清单不适用 |
| 步骤、条件分支、调用路径或结构连接 | 流程图 / 关系图 | 区分顺序、分支、依赖及方向；图中只画已知关系 |
| 历史事件、发布日期、版本演进 | 时间轴 | 保留日期精度与已发生 / 计划状态；无日期的操作步骤用步骤列表或流程图 |
| 分类、目录、隶属或实体关系 | 树状图、分组列表、ER 图 | 按层级、连接或实体字段选择，不把同级清单画成调用链 |
| 单个对象的属性、档案或概要 | 键值块 | 多对象需要横向比较时优先用表格；独立条目按扫描任务决定是否用卡片 |
| 结论、提醒、限制及补充资料 | 提示条、短说明、折叠区 | 关键限制留在主内容旁，低优先级细节按需展开 |

一块信息可以组合组件，例如趋势图配明细表、流程图配例外说明；同一事实不再重复写成长段解释。组件的数量与内容复杂度匹配，无需凑齐某一套组件。

密集内容、对比页、时间线与混合页面的编排参考：[内容与布局模式](references/layout-patterns.md)。需要自动绘制图形或参考整页布局时，读 [渲染入口与接入方法](references/rendering.md)。

## 先编排整页，再完成组件

1. **建立内容与功能清单。** 读取目标页、专用 CSS、依赖 JS、数据与站点入口。记下核心事实、重复信息、独有条件、来源、锚点和交互钩子。
2. **确定阅读主线。** 识别页面主要任务，建立“现有内容 → 信息关系 → 组件 → 所在区域”的映射。用简短说明告诉用户主要重组方向；已有授权范围内继续实施。
3. **安排整体布局。** 确定主内容、对照内容和补充内容的先后。需要对照的区块邻接；宽表与复杂图可通栏；解释紧贴对应图表；细节可折叠。选择顺序阅读、并列对照、主辅或分组检索等布局，不把每段文字机械切成卡片。
4. **落地表达。** 优先复用适用的本站组件；缺少合适组件时，在目标页资源中补充。复杂图形使用技能内置渲染入口计算坐标，参考页只作素材与布局参考，再接回原站点。
5. **统一视觉与响应式。** 让主次关系同时体现在宽度、位置、字号、留白和强调色中。处理整页密度、区块高度差和阅读节奏，再处理局部细节。
6. **核对事实与使用体验。** 按下方验收项检查、截图、修正。汇报内容如何重新表达、主要布局变化及验证结果；不自行提交或推送。

## 本仓库的视觉基础

- [site-nav.css](../../../assets/site-nav.css)：基础识别色、字体、站点壳与导航。
- [design-tokens.css](../../../assets/design-tokens.css)：语义色、字号、间距、圆角及通用组件。
- 样式引用顺序为 site-nav.css → design-tokens.css → 页面 CSS；缺失时补齐引用。
- 主文字、说明、弱化信息分别优先用 --ink、--muted、--faint；区块与内部分隔分别用 --line、--line-soft。
- 优先复用站点字号、间距与圆角阶梯，主题强调色按内容保留或协调。列数、图形比例、断点与行高根据内容和可读性确定，不为了变量化而构造缺乏意义的计算。
- 语义色与数据编码分开：支持 / 警告 / 不支持使用站点语义色；系列、阵营、季节使用有图例的分类色。不要仅靠颜色表达重要区别。
- site-callout 用于结论与提醒，site-badge 用于支持状态，site-kv 用于键值资料，site-timeline 用于时间演进。它们是可选的复用基础，组件能力不限于这四种。
- 新增样式以页面前缀隔离。图表和组件跟随当前页面主题，不直接引入参考项目的全局主题、页面工具条或暗色模式。
- 文字保持可读，说明通常 11–12px、正文 13–14px，避免低于 10px。复杂图不能通过无限缩小来适应手机；改方向、分段或在图内局部滚动。

## 图形生成与实现边界

技能内置固定版本的 Answer me with HTML 渲染器和隔离入口，需要 Node.js 20+，无需另外安装该技能或 npm 依赖。用结构化草稿表达关系，渲染器负责坐标、图形和参考页面排版。

```bash
node <本技能目录>/scripts/render-reference.mjs /绝对路径/内容草稿.md
node <本技能目录>/scripts/render-reference.mjs --help-component sequence
```

入口仅把参考结果写入自己新建的临时目录，关闭自动打开和更新检查，不读取或修改用户的 Answer me with HTML 配置。具体草稿语法、CSS 依赖、SVG ID 冲突及接入步骤见 [渲染参考](references/rendering.md)。

生成图表属于页面编排范围，不需要再开启一个独立制图任务。新增功能、全站改版、联网取数或添加大型运行时依赖不因本技能而自动获得授权；按用户本次要求判断范围。保留原功能需要的脚本，新图优先采用可离线展示的 HTML / CSS / SVG。

## 验收与交付

- **内容保真：** 对照初始清单核对数值、单位、日期、限定条件、来源和独有事实；记录合并后的落点，允许文案等义变化，不用逐字相等代替事实检查。
- **表达正确：** 图形节点、边、先后关系、状态和数据与原内容一致；对数轴、非零基线、不同单位和不同统计口径需明确标注。
- **功能保留：** 实测受影响的复制、筛选、排序、折叠、锚点与键盘操作；核对 ID 唯一、引用存在、原事件仍能触发。
- **整页效果：** 在桌面及至少一个 ≤520px 窄屏各截图并查看；检查主次、扫描路径、密度、对齐、留白、标签截断、箭头连接和局部滚动。只读截图不能代替交互检查。
- **工程范围：** 无非预期的整页横向溢出、外部资源或样式泄漏；新增脚本执行相应语法 / 行为检查，运行与变更有关的现有检查及 git diff --check。
- **交付说明：** 简述组件选型与整页编排的主要变化、验证结果和实际限制。不自动提交，不因美化附带改写其他页面。
