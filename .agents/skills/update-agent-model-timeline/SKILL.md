# 更新 Agent 与模型演进

## 范围

- 入口：[模型演进](../../../ai-model-timeline.html)（仅 `model`）与 [Agent 演进](../../../ai-agent-timeline.html)（仅 `agent`）。先读对应页面的数据及共享 `assets/ai-timeline.js` / `.css`，保留已有未提交改动。两个专题入口只收于 `ai.html`，不加入主导航。
- 普通内容更新沿用布局、筛选、排序与配色，不改其它页面或站点导航。用户本次明确要求优先。
- 产品页头仅显示公司名和产品名，不显示产品介绍或节点数量。
- 模型页从 2020 年起维护关键历史；日常查新按最后节点增量核验，历史补漏按用户要求的年份检查缺口，不每次全量重建。

## 每次更新

1. 以用户指定日期为截止日，未指定时使用会话当前日期。先运行下方校验，读取各品牌最新节点和已有来源；不能仅搜索最新型号后追加。
2. 按 [来源索引](references/sources.md) 检查已关注品牌：日常更新用查新入口，历史回溯用原始报告与固定仓库快照；补旧记录或遇到日期冲突时，按需读 [历史日期笔记](references/history-dates.md)。公告、权重与平台上线分别确认口径。
3. 打开官方原文，记录日期、发布状态、关键变化与永久链接。搜索摘要和网页抓取时间只能提供线索；动态文档的“最近更新”日期不能当成模型发布日期。每个品牌说明检查到的资料范围，访问失败或未找到新节点时如实记录。
4. 新增前按品牌、类型、日期、标题查重；错误日期、链接或状态仅在用户明确指示时修正。原文不能核实时，不把推测作为已发布事实，也不因链接暂时不可达就删除旧历史。
5. 完成事实核验后，仅在用户明确指示时更新页头、页尾的检查日期与实际品牌数量；“截至”指本次查新范围，不代表所有历史记录都重新逐条核实。用户规模统一维护在 `ai-user-scale.html`，时间图不再展示用户规模数据、小注或专题说明。
6. 执行完成检查，简短报告新增、修正、检查日期与未覆盖的来源。需要定时更新时，只有用户明确要求才另建自动化；本技能可直接手动调用。

## 可重复校验

从项目根目录运行（截止日用本次实际日期替换）：

```sh
python3 .agents/skills/update-agent-model-timeline/scripts/audit_timeline.py --as-of 2026-10-09 --check-js
```

脚本默认只读校验两个页面，输出各品牌最新节点与事件数量，检查每页两段 JSON、页面类型、日期、引用、重复记录、来源 URL 和页尾品牌数量；`--page ai-model-timeline.html` 可只检查模型页。`--check-js` 用本机 Node 校验页面脚本（包含共享脚本）。脚本不联网，不能代替事实核验。

## 数据结构

- `timeline-products`：`id / name / company`，产品 `id` 唯一。
- `timeline-data`：`brand / kind / date / title / desc / source / tag`；`brand` 引用产品 `id`，模型页的 `kind` 只能为 `model`，Agent 页只能为 `agent`；日期通常为 `YYYY-MM-DD`；原文只披露月份时用 `YYYY-MM` 并设置 `datePrecision: "month"`，不能补造日。
- 两页保持同一组品牌 ID；`codex` 在模型页显示为 OpenAI，在 Agent 页显示为 Codex，勿因标题不同改动历史品牌 ID。正文 `data-timeline-kind` 标记所属类型。

## 更新约束

- 日常更新仅追加新增内容（新节点及其来源链接）；既往更新已写入的页头页尾检查日期、口径说明与已收录节点一律不再改动，除非用户明确指示修正或重新核验。
- 新增或修正事实须联网核验，优先页内 `#sources` 的官方公告、Changelog、模型仓库；每个事件保留对应来源链接。无法核实精确日期时说明缺口，不编造日期。
- 维护来源时区分动态入口与历史证据：用具体公告、论文版本、提交 SHA 和 PDF 页码固定出处。官方入口迁移且核验后再更新索引；不要把本地临时路径写入技能。
- 回溯早期历史时，可用模型团队原始论文、官方历史仓库快照和公司招股书；区分内部使用、公开权重、API 与产品搭载。网页归档日、论文发布日期和仓库最新提交日期不自动等于模型首发日。
- 按事件实际发布日期记录，区分技术报告、权重开放、API 上线、产品发布及 Beta / GA；不把模型 ID 中的快照日期当发布日期。Agent 产品、框架、协议、接口须在标签或简介中区分，不夸大为独立产品。
- 只收录重要里程碑，简介用一句话说明关键变化，不写宣传语或主观排名。新增前查重，不重排无关数据；已收录记录仅在用户明确指示时修正。
- 固定展示 `timeline-products` 中的全部产品（包含 MiniMax），不显示产品选择组件；保留年份筛选与年月点击排序，不恢复事件类型切换。未经用户要求，不恢复豆包、混元，也不自行扩展关注品牌。
- 增删产品时同步检查两页产品注册、事件、默认筛选、资料来源及页尾品牌数量，避免残留或孤立引用。
- 用户规模与相关统计来源收于 `ai-user-scale.html`，由项目 `update-ai-user-scale` 技能维护，不重复嵌入时间图。

## 完成检查

- 校验两页各自的两段 JSON、品牌引用、事件类型、重复节点、数量文案及共享 JavaScript 语法；确认年份筛选和年月排序引用正确数据。
- 运行 `git diff --check`；涉及结构或交互时运行 `node --test tests/site-system.test.mjs`，按改动验证相关行为。
- 简短说明更新内容与事实来源；仅完成本次请求，不自行提交、推送或发布。
