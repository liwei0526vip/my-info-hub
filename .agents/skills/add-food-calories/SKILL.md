# 添加食物热量

在生活页维护方便日常记账的食物热量速查表，保持简单、清新、小巧、信息密度高。用户本次的明确要求优先于以下默认约定。

## 项目入口

- 页面：[life.html](../../../life.html)，只编辑 `#food-calories` 内的相关记录。
- 样式：[assets/life.css](../../../assets/life.css)。普通内容新增沿用已有样式，不必改 CSS。
- 操作前读取当前表格和相关样式；以文件中的最新内容为准，避免重复添加同一种食物或覆盖已有记录。
- 这是静态 HTML 项目，无需构建、数据库或表单。此 skill 不扩展日常菜单、其它页面或站点导航。

## 份量与数据口径

- 食物适合按个计数时，优先估算普通单个或单根的可食部分重量，例如鸡蛋、鸡腿、包子、苹果、西红柿、黄瓜。金针菇等不便按个计量的食物，默认按 100 g 可食部分记录；用户指定份量时按指定份量。
- 贝贝南瓜按用户指定固定记录 **100 g 可食部分**，不按单个大小估算份量。
- 豆腐脑按用户早餐习惯记录为 **咸味带卤、300 g 成品**，采用匹配的带卤数据换算；总膳食纤维没有可靠值时保留 `—`。
- “普通大小”没有统一标准。联网核对常见份量；大小拿不准时交叉参考权威份量数据、实际包装净重与个数。选一个方便日常记账的代表重量，不用大规格或迷你规格代替普通规格。
- 联网核对新增或修改的营养数据，优先使用中国疾控中心食物营养成分平台、中国食物成分表、USDA 等权威数据，或有清楚营养标签的产品来源。品牌没有可靠公开数据时可用同类食品估算，在来源说明中明确这一点。
- 区分生鲜、水煮、卤煮、蒸制等状态，尽量选择匹配做法的数据。使用生鲜数据时不自动加上炒菜用油；另用参考数据估算做法时说明依据。
- 每项热量及成分同时记录本份值 A 与每 100 g 值 B。B 优先使用原始参考数据，保留计算精度，不能从已舍入的 A 倒推；鸡蛋、鸡腿等个人指定热量的 B 则按指定热量 ÷ 本份克数 × 100 折算，并在来源说明中注明个人口径。已有本份值不因新增每 100 g 展示而改动。
- 从每 100 g 数据换算：`本份数值 = 每 100 g 数值 × 本份可食重量 / 100`。热量取整数千卡，四项成分保留一位小数，零值写 `0`；用原始精度计算后再取整。只有 kJ 时除以 `4.184` 换成千卡。
- 各成分须属于同一种食物和相同份量。补用其它来源时核对品种、状态、可食部分和单位，记录各自出处；不要把干辣椒数据用于鲜辣椒，也不要直接把粗纤维当作总膳食纤维。
- 膳食纤维缺失时继续查找可信来源，不把缺失解读成没有纤维。仍无法核实则写 `—`，并在来源说明中注明未提供数据。
- 保留个人统计例外：鸡蛋热量 **75 千卡**、说明“水煮”；鸡腿热量 **150 千卡**、说明“卤煮”。未经用户要求，不用营养公式或其它来源改回这些热量。个人指定热量和参考成分的依据分别说明。
- 素菜包子统一涵盖韭菜鸡蛋、地三鲜等素馅口味；其未提供的纤维按用户个人记录口径写 **0**。此例外不推广到其它食物，也不表示来源测得含量为零。

## 表格展示

- 字段顺序沿用：分类、食物、说明、克数、热量、蛋白质、脂肪、碳水、纤维。实际营养四项共用 `.nutrient-column`，内部用 `.nutrient-grid` 按这个顺序放四个数字。
- 食物名称只写简短名称，如“鸡蛋”“苹果”“辣椒”；做法、品种、大小放在说明列，如“水煮”“卤煮”“中等”“青尖椒”。不在名称中堆描述，不刻意强调桃子去核等细节。
- 克数只写 `150 g` 这样的数值与单位，不写“约”“估算”“1 个”“1 只”“1 根”。按个计量的依据保留在来源说明中。
- 热量和四项成分同时记录 A 与 B：A 对应本行克数，B 对应每 100 g。页面顶部保留“显示每百克数据”勾选项，默认不勾选、仅显示 A；勾选后显示 `A/B` 及对应说明。沿用 `.measure-pair`，A 使用 `.measure-current`，B 使用 `<small class="measure-per-100">/数字</small>`，以小号灰字和斜杠紧跟 A，不换行、不重复单位；表头只写“热量”，数值单位统一为千卡，不在表头重复。B 数据始终保留在 HTML 中用于排序，不因隐藏而删除。克数恰好为 100 g 时也保留同一结构。
- 保留五个数值表头的排序按钮及 `assets/life.js`。排序按钮默认隐藏，仅勾选“显示每百克数据”时显示，取消勾选后同步隐藏。按钮按各分类内部的 B 值排序，首次降序、再次升序；相同值保留原始顺序，缺失值始终排到分类末尾。新增记录继续使用 `.measure-per-100` 和四项成分的既定顺序，确保排序能够读取正确数值。
- 热量的 A 值使用默认正文色，不用绿色强调；B 值继续使用小号灰字。
- 成分名称只放在表头，行内不重复“蛋白质”“碳水”“纤维”等字段。表头不再追加末尾的 `g`，也不为单位另占一行。
- 食物列的表头和内容左对齐，其它数据列的表头和内容居中。分类单元格沿用当前左侧窄列，跨行垂直居中。
- 沿用紧凑行高和现有移动端布局，不新增大卡片、表单、占位信息、可见参考资料区或页脚。
- 食物名用 `.food-source` 链接到真实数据来源，保留 `target="_blank"` 与 `rel="noopener noreferrer"`。份量依据、估算做法和个人口径放在简短的 `title` 中；补充来源可在相邻 HTML 注释中保存 URL，便于追溯。

## 分类与重点成分

- 优先归入现有蛋类、肉类、豆类、主食、蔬菜、水果分类；仅在确有需要时新增短分类。
- 同类记录放在同一个 `tbody` 中，使用已有 `aria-labelledby`、`scope="rowgroup"` 和 `rowspan` 合并分类标签；不重复分类文字，不增加整行分类标题。
- 只对有代表性的成分加重点色，不要求每种食物都有重点，也不按一行里最大的数字机械判断。结合食物特点及相同重量下的含量判断，保留已有重点选择。
- 重点仅用文字颜色表达，不加背景色、徽章、额外加粗或深浅两档。沿用这些类和 CSS 变量：

| 成分 | 数值 span 的 class | 颜色变量与当前颜色 |
| --- | --- | --- |
| 蛋白质 | `nutrient-focus nutrient-focus--protein` | `--life-protein`，柔和紫色 `#80569b` |
| 碳水 | `nutrient-focus nutrient-focus--carbs` | `--life-carbs`，红色 `#c43e3e` |
| 膳食纤维 | `nutrient-focus nutrient-focus--fiber` | `--life-fiber`，蓝色 `#2862a3` |

重点色仅放在 A 的 `.measure-current` 上，B 始终为灰字；未突出成分用普通 `.measure-current`，不要用页面的绿色表示营养成分重点。用户后续调整颜色时，以 CSS 中的最新变量为准。

## 完成检查

- 核对实际记录数并更新“n 种食物”，同步更新受影响分类的 `rowspan`；确认每条记录仍有四个营养值。
- 检查份量、换算、舍入、营养值顺序及来源说明是否一致，确认每行有五组 A/B，尤其不要把每 100 g 数值误填到本份 A 中；核对个人指定热量的 B 换算与来源数据的舍入。
- 查看本次改动并运行 `git diff --check`。涉及共享结构或样式时，按范围运行项目已有检查；普通记录新增不必新增测试文件。
- 最后简短告知已添加或更新的食物、份量口径；使用外部数据时给出支持本次数据的来源链接，不长篇解释。仅完成本次请求，不自行提交或发布。
