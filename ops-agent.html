前言

从自动化运维，走向智能协同。

定位与目标

技术
AI 原生：大模型 + Agent + RAG（知识增强）+ Memory（经验记忆）+ 权限受控执行。
目标
从设备管理转向业务保障与持续运营，提高效率、降低故障影响。

能力与集成

能力
感知 → 规划 → 执行 → 反馈；关联分析、根因定位、提前识别风险与协同处置。
集成
开放架构，融合既有监控、日志、知识、协同通道与基础设施。

运维面临的挑战

环境与数据

环境
云、容器、微服务等架构并存，依赖复杂，故障需跨系统、跨领域分析。
数据
指标、日志、告警、配置与业务数据分散，缺少统一关联分析，难支撑决策。

经验与治理

经验
自动化擅长明确场景；复杂诊断与业务影响评估依赖专家，经验难沉淀复用。
治理
权限、审批、责任追溯与合规审计要求提升，AI 执行必须可控、可解释。

AI 推动运维模式升级

从经验驱动，经数据驱动，走向目标驱动。

四阶段对比

阶段核心方式作用与边界
人工凭经验分析与执行。效率低，标准化不足，经验难复制。
自动化脚本、固定规则与预定流程。减少重复操作；复杂诊断与动态场景仍靠人判断。
AIOps数据关联、异常检测、预测与根因分析。偏重分析识别与辅助决策，仍需人工进一步分析和执行。
AI Agent结合知识、实时数据与工具，理解目标、规划并协同执行。从辅助决策延伸到发现、研判、处置的闭环，在权限边界内与人协同。

应用与分工

应用
故障分析、风险识别、巡检评估、变更验证。
分工
AI 承担重复、规则化与数据密集工作；人聚焦架构优化、风险治理与业务保障。

产品定义

面向企业级 IT 基础设施的 AI 原生智能运维系统。

场景与机制

场景
大规模分布式系统，贯通网络、系统与应用层。
机制
大模型负责推理，Agent 负责执行，人机协作构成安全责任模型。

目标与行动

任务
理解运维目标 → 关联知识 → 规划任务 → 调用专业工具执行。
闭环
故障发现 → 根因诊断 → 策略决策 → 闭环处置。

产品定位

企业智能运维体系中的 AI 执行与协同中枢。

体系位置

层次
复用既有监控、日志、CMDB、ITSM、自动化及知识系统，在其上构建智能能力层。
服务
连接运行数据、组织知识与运维工具，支持运维、业务与研发人员协同。

四类核心问题

孤岛
Agent 串联数据、流程与工具，形成信息理解、任务编排和闭环执行链路。
专家
结合模型推理、知识增强与拓扑分析，将专家排查与处置经验沉淀为可调用的 Skill。
经验
持续积累规范、案例、流程与最佳实践，将个人经验转为组织知识资产。
断点
连接原因分析、策略生成、工具调用与执行验证，在权限控制与人工确认下完成处置。

产品设计理念

AI 原生

以模型与 Agent 为核心，贯穿需求理解、知识利用、任务规划、工具执行与经验沉淀。

开放融合

通过标准接口与开放协议接入既有数据源、工具及第三方能力，支持跨平台编排与执行反馈，保护既有 IT 投资。

安全可信

按风险分级：低风险查询与分析自动完成；配置修改、服务启停、批量执行等关键操作经既有审批与人工确认。分析、工具调用、执行与用户操作全程留痕，形成可追溯的审计链。

持续成长

以知识增强与经验记忆持续沉淀故障、规范、流程、最佳实践及可复用技能，让平台能力、组织知识与运维流程共同演进。

产品核心能力

智能交互

自然语言完成查询、分析、巡检、知识检索与任务下发，结构化输出判断依据和处置建议。

智能分析

自动采集指标、日志与业务数据，结合拓扑、知识和历史经验跨层关联，定位根因与业务影响路径。

主动运维

关联 Prometheus 数据并支持 PromQL 查询，融合实时状态与历史趋势，识别异常模式、预测容量与性能风险并提前预警。

流程闭环

融入既有监控、协同、审批与变更流程，贯通发现、分析、执行和反馈；计划任务记录“何时何地做什么”，技能复用“怎么做”。

自动执行

支持定时与告警触发，受控执行远程、批量任务，管理超时、目标范围与反馈；按风险和权限自动执行、审批后执行或仅输出计划，全程留痕。

移动化运维

通过钉钉等移动入口接收告警、报告与审批消息，完成状态查询、故障分析、任务确认和指令下发。

AI 原生核心技术能力

技术模块 核心作用 关键机制
OPAR 运行框架 核心作用组织智能体持续运行的闭环。 关键机制

Observe · 感知：融合访问、服务、指标与日志，识别环境变化和异常趋势。

Plan · 规划：结合状态、知识、历史经验与依赖，提出假设，按优先级规划诊断路径和策略。

Act · 执行：调用技能、命令行、REST API 与流程，将分析落实为受控行动。

Reflect · 反馈：复盘结果、处置过程及用户反馈，将有效路径和经验沉淀到知识与记忆，进入下一轮闭环。
模型编排 核心作用按任务匹配能力，平衡效果、成本与响应效率。 关键机制

多模型：兼容 OpenAI、Anthropic API 标准及国产模型，按业务、部署与安全要求选型。

工具注册：明确用途、输入、风险与边界，按任务分发；系统提示规范探索、规划和执行顺序。

任务编排：复杂问题采用多轮推理与多工具协同，标准任务复用技能。
知识与经验 核心作用理解组织环境，复用历史处置经验。 关键机制

RAG：检索组织文档、设备手册与规范，提供上下文，支持命令理解、配置核对、语法匹配与处置建议。

Memory：按主机沉淀故障案例、分析路径、方案与最佳实践，供后续诊断复用。
技能与工具 核心作用技能封装方法，工具提供实际操作手段。 关键机制

Skill：内置巡检、部署与日志分析等技能，将 SOP、脚本、流程和专家经验封装为可复用、可共享的方法。

Tool Calling：统一查询、远程与批量命令、文件传输和 REST API 调用；区分只读与有副作用工具，管理条件、参数及结果。

接入扩展：结合标准接口与设备文档理解，减少新增设备和系统的专用插件开发与重复适配。
拓扑推理 核心作用判断业务影响，辅助定位根因。 关键机制

关系建模：统一网络、应用拓扑与业务依赖，识别节点层级、角色、上下游邻接关系与根节点路径。

路径分析：结合运行数据沿依赖链判断影响，缩小排查范围，定位关键节点。
流程与协同 核心作用管控执行，衔接既有审批与长期调度。 关键机制

HITL：AI 承担标准任务，关键环节由人判断；展示工具、目标、状态及待确认节点，涉及业务影响或配置变更时按策略确认。

风险分级：L1 只读、L2 可逆、L3 难以逆转、L4 不可逆。

权限模式：默认询问、自动执行、只出计划、只读。

流程调度：对接审批与流转，将运维动作沉淀为计划任务，调度触发后通过协同通道通知结果。
运营治理 核心作用管理用量、安全边界与审计追溯。 关键机制

用量成本：按用户、团队、任务与模型统计调用和资源消耗，管理 Token 用量、配额及异常消耗。

访问权限：按角色、资源与 API Token 管理设备、系统及执行能力的访问边界。

凭据保护：密码、SSH 私钥与密钥口令以 AES-256-GCM 落盘加密，不直接暴露给模型，执行时受控调用。

全程审计：记录用户交互、分析、执行和结果，支持追溯与责任界定。
