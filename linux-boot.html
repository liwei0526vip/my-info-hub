Linux 系统启动

从第一条指令到用户登录，读懂启动链路、根目录交接与服务组织。

启动的本质：逐步建立下一阶段所需的运行条件。

看清谁在执行、准备了什么、如何衔接下一步。

01 启动全貌 02 根目录交接 03 服务与登录 04 实机观察
01 / 启动全貌

六个阶段，一条启动链路。

加载文件不等于执行程序。

主线示例：常见桌面 / 服务器 Linuxx86-64 · UEFI · GRUB · initramfs · systemd
01

UEFI 固件

CPU 复位后，从规定入口执行固件代码。
初始化关键硬件，选择启动项。

这一阶段做什么

  1. CPU 复位

    进入初始状态，从复位入口执行主板 Flash 中的 UEFI 固件。

  2. 准备硬件

    准备内存、总线和启动存储，按需启用显示与输入。

  3. 选择启动项

    读取固件配置，按启动顺序定位设备与 EFI 文件；本地入口通常位于 FAT 格式的 EFI 系统分区（ESP）。

  4. 加载并执行

    将 EFI 引导程序读入内存并执行；安全启动可先运行 shim，由它校验并加载 GRUB。

UEFI 固件与 EFI 程序是两段程序，均由 CPU 执行。传统 BIOS 通常读取启动盘的引导扇区并执行其中代码。

交给 EFI 引导程序（如 GRUB）

    按 GRUB 配置默认启动，也可用菜单选择系统、内核版本、恢复入口，或修改参数。

    转入内核启动入口。

initramfs：GRUB 加载，内核解包。也可换用其他引导器，或由 UEFI 直接加载带 EFI stub 的内核。

控制权交给内核
03

Linux 内核

建立进程、内存、文件与设备的运行基础。

LinuxKERNEL
内存管理进程调度设备驱动文件系统

这一阶段做什么

  1. 接收参数

    读取 GRUB 传来的根设备等参数。

  2. 初始化内核

    管理内存、建立虚拟地址空间（进程的内存视图），初始化调度、中断/异常、内建驱动与文件系统支持。

  3. 解包 initramfs

    展开其中的文件：

    内存 · 临时根/
    /init工具驱动模块
  4. 启动 /init

    以 PID 1 运行，进入早期用户空间。

用户态启动后，内核仍持续运行。固件做早期准备，内核以自身驱动管理硬件。

执行第一个用户态程序 /init

02 / 根文件系统的交接

为什么需要 initramfs？

先用一个小环境，接通真正的系统。

困难：根与工具相互依赖

访问真正的根文件系统，可能需要驱动、解密或逻辑卷工具；而这些文件可能就在尚不能访问的根里。

缺少它：若内核能力不足，又无早期工具，可能无法准备根设备或挂载根，启动会卡住。

initramfs

解决：先备好早期工具箱

提前将所需模块、工具和 /init 打包成 initramfs 归档，由引导器提供或内核内建。

内核解包到内存后运行 /init，由它准备设备、挂载并切换到真正的根，继续启动系统。

省略 initramfs：所需驱动与文件系统支持已内建，且无需早期工具时，内核可直接挂载目标根并启动初始化程序。

省略切根：仍使用 initramfs，以解包后的内存根作为最终根，直接在其中运行系统。

03 / 服务、并行与登录

systemd 如何把系统组织起来？

根目录交接后，先决定启动谁，再约束先后。

PID 1 的职责
收养符合条件的孤儿进程、回收退出状态；编号限定于 PID 命名空间，容器可有自己的 PID 1。
单元 unit：管理对象
.service 服务 · .mount 挂载 · .socket 套接字 · .target 目标。
目标 target：组织启动
default.target 通常指向 multi-user.target（多用户）或 graphical.target（图形登录），按依赖组织启动。
!

After= 不会自动拉起对方；Requires= 不会自动规定先后。

示例：Web 依赖数据库，希望启用缓存。

# web.service · 节选
[Unit]
Requires=database.service
Wants=cache.service
After=database.service
如果数据库或缓存启动失败，会发生什么？＋

本例中，Requires= 配合 After=：数据库激活失败，Web 不启动；Wants= 使缓存失败不阻止 Web。

条件跳过、正常自行退出不等同于激活失败；Requires= 不保证被依赖服务一退出，本服务就退出。

04 / 实机观察

用命令，观察真实启动。

对照前述流程观察常见 systemd Linux；输出依发行版、权限与日志配置而定。

观察 Linux 启动的命令、输出含义与判断边界
观察什么命令输出含义与边界
内核参数
cat /proc/cmdline

当前内核命令行。root=UUID=… 指定目标根；ro 通常表示初始只读，后续可重新挂载为可写。参数由内核或早期用户空间解析。

无法还原固件与引导器的完整执行过程。

当前 PID 1
ps -p 1 -o pid,comm,args

查看当前 PID 命名空间的初始化程序。

无法据此判断早期 /init 的实现，或是否使用了 initramfs。

当前根目录
findmnt /

查看当前挂载命名空间中 / 的文件系统、来源与挂载选项。

不反映启动时的切根历史。

本次启动日志
journalctl -b -k
journalctl -b

分别查看本次启动的内核消息与全部已收集日志，追踪设备、挂载和服务启动。

仅限有权限读取且保留的记录，通常不含固件细节。

耗时与顺序链
systemd-analyze
systemd-analyze critical-chain
systemd-analyze blame

依次看启动时间、部分关键顺序链、单元初始化耗时排序。

并行耗时不能直接相加；blame 首位不等于瓶颈，需结合依赖、设备等待与就绪方式判断。
