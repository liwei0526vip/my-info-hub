Harness Engineering

让 Agent 稳定完成任务

把目标、信息、行动、验证和修复，组织成一套能持续运行的执行闭环。

模型提供理解与生成能力，外围系统负责工具、状态、反馈和运行边界。可靠交付需要二者配合：既能推进任务，也能发现偏差、恢复执行，并按明确标准结束。

三个概念，各解决一个问题

Prompt、Context、Harness 的工程关注点
关注点要解决的问题
Prompt指令任务怎么讲清楚目标、约束、输出要求。
Context上下文信息怎么给对相关事实、工具结果、当前进度。
Harness执行系统任务怎么可靠完成安排执行、校验结果、处理失败。

三者相互配合。任务越长，越需要把信息供给、执行和反馈一起设计。

三个工程关注点

信息与状态
按需读取相关资料，将规则、任务材料、运行进度分开。保存已完成步骤、待解决问题和证据位置，方便长任务续接。
执行与工具
把目标拆成可检查的小任务，明确工具输入、返回结果和权限边界。失败信息要具体，便于判断是参数、权限还是临时故障。
验证与恢复
用测试、实际页面操作、日志或业务结果验收。将失败证据送回下一轮；必要时重试、换路径或恢复到稳定状态，并设置停止条件。

由视频的六层框架合并整理，用于理解机制与排查缺口。

示例：修复登录失败

说明性推演
验收
正确密码能登录，错误密码被拒绝，原有权限检查继续生效。
执行
读取认证代码、错误日志与相关测试；复现问题后修改。
反馈
运行针对性测试与相关回归，实际操作页面。失败时提供输入、预期、实际结果和日志，修复后再次验证。

从最小可用流程开始

先选一组真实任务，明确完成标准，记录完成率、人工接管率、耗时和成本。优先补齐最常见的失败环节，每次改动用相同任务与相近预算比较，再用新任务检验。

短任务采用清楚的指令、必要工具和直接验收。长任务再增加状态交接、独立评估与恢复机制；模型或任务变化后，重新检查这些机制的收益。

失败时，先定位缺少的信息、工具、状态或检查，再补齐对应能力。
