从算法征集到标准落地以 NIST PQC 为例
  1. 征集提交算法规范、参数与参考实现
  2. 多轮评审公开分析安全性、性能与实现风险
  3. 选定标准化编写标准，可先公布编号与算法名称
  4. 草案征评草案列明标准编号、算法名称与参数，公开征评
  5. 定稿发布审批发布，编号、名称与规范正式定稿
  6. 部署应用确认库支持、协议适配与互通

各算法的评审轮数与耗时不同；实现和协议适配可并行推进。有合规要求时，还需核对具体模块的验证证书。

参考：NIST 标准化流程、编号与命名示例：FIPS 203 草案、CMVP 模块验证。

协商与报文检查

  • 握手体积X25519MLKEM768 的客户端 / 服务端 key_share 分别为 1,216 / 1,120 B，未计封装与证书；检查中间盒、分片与 MTU。
  • 纯 ML-KEMMLKEM512 / 768 / 1024：0x0200 / 0x0201 / 0x0202；使用独立规范，OpenSSL 3.5 需配置启用。
  • 其它混合组MLKEM1024X448（0x11EF）与 curveSM2MLKEM768（0x11EE）仍为草案；后者已由 OpenSSL 4.0 实现。
  • 旧组X25519Kyber768Draft00：0x6399，IANA 已标记 obsolete，使用正式 ML-KEM 组替代。
  • QUIC / HTTP/3使用 TLS 1.3，但抗量子支持仍须核对所用 TLS 栈及协商配置。

RFC 10024 §4、IANA 注册表、纯 ML-KEM 规范进展。SLH-DSA 也有 TLS 草案和注册项，实际协商能力取决于实现。

抗量子密码解决什么

用现有计算机可运行的新算法，抵御未来大规模容错量子计算机的攻击；它与量子密钥分发（QKD）是不同路线。

风险对应关系

RSA、DH、ECC含 ECDSA、SM2 等
Shor 算法威胁密钥建立与签名
AES、哈希函数
量子搜索削弱部分安全余量，影响取决于参数与用途

长期数据先保护

医疗隐私、研发成果与长期档案可能遭遇“先截获，后解密”；已有密文的保护取决于当时的密钥建立方式。

Q-Day 尚无确定年份

迁移同时受数据保密年限和系统改造周期约束，不宜等待实际破解发生后再行动。
